    Applications¶

    Experimental applications compose BRepAX geometry evaluation with host-side CAD preparation. Their individual contracts define differentiation and input scope.

    STEP through-hole editing¶

    prepare_hole_edit recognizes cylindrical through-holes in a supplied B-Rep. It can edit selected radii and centers without reconstructing the stock's modeling history. The JAX model moves hole walls and adjoining planar boundaries together; the host rebuild method produces a new OCCT shape for further use or STEP export.

    import equinox as eqx
import jax
import jax.numpy as jnp

from brepax.experimental.applications.hole_edit import prepare_hole_edit
from brepax.io.step import read_step

jax.config.update("jax_enable_x64", True)
shape = read_step("part.step")
all_holes = prepare_hole_edit(shape)
# Select one hole by its input face ID; other features remain fixed.
face_id = all_holes.holes[0].face_id
edit = prepare_hole_edit(shape, [face_id], deflection=0.0001)
model = edit.model
radii = (model.reference_radii + model.upper_radii) / 2
assert bool(eqx.filter_jit(model.is_valid)(radii))
volume, derivative = jax.jit(jax.value_and_grad(model.volume))(radii)
areas = jax.jit(jax.vmap(model.surface_area))(
    jnp.stack([model.reference_radii, radii])
)
edited_shape = edit.rebuild(radii)

    Center motion uses an optional second argument, center_shifts, with one world-coordinate displacement vector per selected hole. It is measured from the original center in input CAD units. The hole axis stays fixed; shifts must be perpendicular to it. Omitting the argument preserves radius-only behavior. For the Z-axis holes in the fixture below:

    shifts = jnp.array([[0.2, -0.1, 0.0]])
assert bool(eqx.filter_jit(model.is_valid)(radii, shifts))
center = model.center_of_mass(radii, shifts)
center_jacobian = jax.jit(jax.jacrev(model.center_of_mass, argnums=1))(radii, shifts)
edited_shape = edit.rebuild(radii, shifts)

    For a reproducible repository example, use tests/fixtures/box_with_holes.step as part.step. Its radius-4 through-hole can be selected and changed to 4.4; the other radius-3 hole remains unchanged. The tests also cover rectangular and round stocks, nonintersecting orthogonal holes, regenerated placements, STEP roundtrips, and independent CAD finite-difference references.

    Contract and limits¶

    • Input must contain one valid outward-oriented solid. Editable holes need a complete empty cylindrical bore, two perpendicular outward-facing planar ends, and clearance from other boundaries. Blind, split, oblique, intersecting and near-boundary holes are rejected. Unsupported inward cylinders appear in edit.rejected; an explicit selection of an unsupported face raises ValueError. A counterbore shoulder is not a valid end for its larger cylinder; the smaller bore through the remaining slab can still qualify independently.
    • Radii, center shifts, hole metadata, returned points and metrics use the input CAD's units. A fixed CadFrame normalizes host preparation and numerical evaluation. By default, the input bounding box is centered and its largest extent becomes 40 working units. The deflection argument is in working units, not the original STEP units. No physical unit is inferred from a numeric coordinate.
    • Preparation requires JAX x64. Recognition and CAD rebuilding run outside jit, vmap and differentiation. Geometry/metric methods support all three; the Boolean validity predicate supports jit/vmap. Keep the prepared model fixed when differentiating with respect to radii or shifts. For direct compilation of a bound model method, use eqx.filter_jit(model.volume); bare jax.jit(model.volume) can fail because the bound Equinox model contains unhashable arrays. Alternatively, JIT a function taking the model as a PyTree argument. Compositions such as the value_and_grad example above also work.
    • Radius bounds are [0.5*r0, r0 + 0.2*clearance]. Center shifts and radius growth share that clearance: norm(shift) + max(radius-r0, 0) must not exceed 0.2*clearance, even when shrinking a hole. Axial shifts are invalid beyond roundoff (64 * x64_epsilon * r0); the residual is projected out. model.is_valid also checks local triangle orientation. Invalid edits return NaN geometry/metrics under JAX; rebuild raises. Gradients at invalid inputs are undefined.
    • Volume and area are rigid-motion invariant; their radius gradients are too. Under positive length scaling s, values scale by s**3 and s**2, and radius gradients by s**2 and s. Centers/vertices transform as points; center radius derivatives rotate as vectors and are unchanged by unit scaling. Rotate center shifts with the geometry. Scalar shift gradients rotate as vectors and scale like radius gradients. The center-of-mass shift Jacobian transforms as R @ J @ R.T and is unchanged by unit scaling. These Jacobians describe transverse motion, with zero axial component; they do not authorize editing the hole depth or orientation. Fresh meshing may change discretization error, so compare within an accuracy budget rather than demanding identical triangulations.
    • Gradients describe a frozen mesh with coupled boundary motion. They do not differentiate OCCT reconstruction or remeshing. Rebuild and independently check CAD before accepting an optimized design; refine deflection when value or derivative accuracy is insufficient. The local validity predicate is not a general self-intersection certificate.
    • Face IDs apply only to the prepared input. Reconstruction unifies connected same-domain faces and edges to remove fill seams; unselected geometry stays fixed, but its face partition can change. Do not assume that Boolean output or a STEP roundtrip preserves face IDs.

    See ADR-0021 for the scope decision.

    Inverse editing¶

    The regression example also imports a four-hole STEP plate, selects three noncollinear holes, fits their radii to independently generated CAD volume and in-plane center-of-mass targets, and validates the rebuilt STEP while preserving the fourth hole. Its Newton iteration checks the Jacobian rank and edit bounds; it is a reproducible example, not a general-purpose optimizer API.

    Another regression solves a selected hole's radius and two transverse center coordinates from independent CAD volume and in-plane center-of-mass targets, then checks the rebuilt STEP and the unchanged neighboring hole. Moving an isolated hole at fixed radius leaves volume and area unchanged; those two measurements alone cannot determine a center position.

    Choose enough independent target measurements. For four coplanar equal-height holes, volume and even the full 3D center of mass need not determine all four radii uniquely. A small mesh optimization residual also does not certify CAD accuracy: check the rebuilt CAD and refine the discretization when necessary.

    brepax.experimental.applications.hole_edit ¶

    Experimental fixed-topology radius and center editing of STEP through-holes.

    Host preparation/reconstruction uses OCCT. The array model couples cylindrical walls and planar end boundaries on one frozen, welded mesh. It does not trace through feature recognition, Boolean rebuilding, meshing, or topology changes.

    PreparedHoleEdit dataclass ¶

    Host result with selected holes, rejected candidates, frame and JAX model.

    holes are ordered like the radius vector; explicit face selections preserve caller order, otherwise original face order is used. Unselected features remain fixed. Host CAD objects never enter the JAX model.

    rebuild(radii, center_shifts=None) ¶

    Rebuild isolated holes in OCCT and restore external coordinates.

    This host operation is not differentiable. Raises ValueError for an invalid radius/shift vector and RuntimeError for reconstruction failure or disagreement with isolated-hole volume, area or center of mass. Input CAD remains owned by the caller; each reconstruction uses an owned copy. Same-domain faces/edges are unified, so unselected geometry is preserved but original face partitions and IDs are not.

    HoleEditModel ¶

    Bases: Module

    Pure array model; differentiate radii and shifts with preparation frozen.

    Each method accepts external-unit radii and optional center_shifts with shape (selected holes, 3). Shifts are world-coordinate vectors from the original centers, perpendicular to the fixed hole axes. Omission means zero shift. Axial components exceeding 64x64_epsilonreference_radius are invalid; roundoff-sized components are projected out. Shift Jacobians are tangent derivatives, with zero axial component, not axial edit support.

    Geometry and metric methods support jit, vmap and parameter differentiation; the Boolean validity predicate supports jit/vmap. Lengths are in the input CAD's units. Use the metric methods for stable evaluation before restoring a potentially large world origin. Scalar measures and their radius derivatives are invariant under rigid placement. Rotate shifts along with the CAD: scalar shift gradients rotate as vectors, while the center-of-mass shift Jacobian transforms as RJR.T. Under positive unit scaling s, volume/area scale by s3/s2 and length gradients by s**2/s. Center-of-mass length Jacobians do not scale. Points and centers transform as points. These laws hold up to CAD tolerance and discretization error after fresh preparation.

    lower_radii/upper_radii bound radii. Shift magnitude plus positive radius growth must not exceed upper_radii - reference_radii. Both use the same clearance budget, including when shrinking the hole. is_valid additionally rejects collapsed or locally reversed triangles. Invalid edits produce NaN geometry/measures; derivatives there are undefined. The validity test is not a general mesh self-intersection or CAD certification algorithm.

    prepare_hole_edit(shape, face_ids=None, *, frame=None, deflection=0.001) ¶

    Prepare bounded edits of full cylindrical through-holes in one solid.

    Accepts a B-Rep returned by read_step; does not assume a stock primitive or a construction history. Each selected inward cylinder must be complete, with two perpendicular planar ends and sufficient clearance. Blind, split, oblique, intersecting and near-boundary holes are unsupported. Rejected inward cylinders are reported; an explicit selection of one raises.

    frame maps input units to working coordinates; by default the bounding box is centered and its largest extent becomes 40 working units. It is frozen during editing. deflection is an absolute WORKING-unit meshing tolerance, finite and positive. Preparation requires JAX x64; it never changes the global JAX precision setting. Input CAD is copied.

    Radius bounds are [0.5r0, r0 + 0.2clearance]. Optional transverse center shifts share the growth budget: norm(shift) + max(radius-r0, 0) must not exceed 0.2*clearance. Moving cylinder samples and neighboring planar samples together preserves the welded connectivity. Geometry outside the radial support stays fixed. These are local edits, not a topology-changing CAD kernel. Mesh orientation may restrict the usable interval further; callers must check model.is_valid.

    Raises ValueError for invalid CAD, unsupported selections, no supported holes, or a mesh that cannot be welded into a closed oriented surface. Unsupported surface evaluators raise NotImplementedError. OCCT extraction failures propagate. Meshing accuracy is not certified by preparation.

    Example

    import jax from brepax.io.step import read_step jax.config.update("jax_enable_x64", True) edit = prepare_hole_edit(read_step("plate_with_holes.step")) radii = (edit.model.reference_radii + edit.model.upper_radii) / 2 assert bool(edit.model.is_valid(radii)) volume, gradient = jax.jit(jax.value_and_grad(edit.model.volume))(radii) edited_cad = edit.rebuild(radii)

    To move a hole, pass center_shifts in external units to the model and rebuild. For a selected Z-axis hole, jnp.array([[0.1, 0.0, 0.0]]) moves its center in X; check the combined budget with is_valid first.

    Circular cut crossing a plate edge¶

    brepax.experimental.contact evaluates the remaining volume of a rectangular plate after a perpendicular circular through-cut, including the transition from an enclosed hole to an open notch. It integrates the analytic boundary and differentiates that same continuous volume. It does not accept arbitrary STEP input or rebuild a solid; the imported-hole API above retains its clearance constraints.

    Use a source checkout containing this experimental module for the example and benchmark below.

    import jax
import jax.numpy as jnp

from brepax.experimental.contact import plate_with_hole_volume

jax.config.update("jax_enable_x64", True)
center = jnp.array([1.5, 0.2])
half_extents = jnp.array([3.0, 2.0])
height = jnp.array(2.0)

def volume(radius):
    return plate_with_hole_volume(center, radius, half_extents, height)

# First contact is at radius 1.5; 1.7 opens the right edge.
value, derivative = jax.jit(jax.value_and_grad(volume))(jnp.array(1.7))

    Use one length unit and local plate coordinates. All parameters support first derivatives; exact contact can have a smooth volume even when the solid's boundary pinches and its mesh is not closed. Moving a fully enclosed hole's center at fixed radius correctly has zero volume derivative. See ADR-0022 for the scope, numerical limitations, and comparison requirements.

    Run the independent geometry and estimator comparison from a checkout:

    uv run --group benchmark python -m benchmarks.contact_transition.run --cad --output /tmp/contact.json

    The output retains failed cases, all declared smoothing choices, finite-difference steps, fresh OCCT and mesh checks, and synchronized execution costs. Ordinary AD of the same analytic primal is included. These bounded comparisons do not establish a general advantage over ordinary AD or arbitrary CAD support.

    brepax.experimental.contact ¶

    Analytic area and first shape derivatives for a circular cut in a rectangle.

    This limited experiment uses Green's theorem and boundary flux, not a sampled indicator or a correction to a future contact event. It does not edit a B-Rep.

    circle_rectangle_intersection_area(center, radius, half_extents) ¶

    Area of a disk intersected with a centered, axis-aligned rectangle.

    All inputs use one length unit. center is in the rectangle's local frame; radius and both half_extents must be positive and finite. Invalid numerical inputs return NaN for the value and first derivatives. Use floating JAX arrays of matching dtype; x64 is recommended near contact.

    Supports jit, vmap, JVP and reverse-mode first derivatives in all arguments, including at circle/edge and circle/corner contacts (C1). The custom JVP integrates normal boundary velocity for the same continuous area as the primal. It avoids differentiating singular arc endpoints whose contributions cancel and arbitrary AD conventions at tied sorted endpoints. Only first derivatives are part of this contract; second derivatives may not exist at contact.

    Scaling all lengths by s>0 scales area by s**2 and length derivatives by s. The local frame must move with the rectangle under rigid transformations. Tiny remaining areas and extreme radius/rectangle ratios can lose relative floating-point accuracy; this is not a general robust Boolean kernel.

    Example::

    area = circle_rectangle_intersection_area(
    jnp.array([1.5, 0.2]), jnp.array(1.8), jnp.array([3.0, 2.0])
)

    plate_with_hole_volume(center, radius, half_extents, height) ¶

    Remaining volume after a perpendicular circular through-cut in a plate.

    The stock is [-bx,bx] x [-by,by] x [0,height]; the cutter spans its full height. The cut may open through edges or corners, unlike bounded fixed-topology hole editing. This function evaluates a scalar; it does not regenerate CAD or accept arbitrary STEP geometry.

    Inputs are floating JAX arrays in one length unit. Positive finite sizes are required; invalid inputs produce NaN values and first derivatives. First differentiation in all arguments and JAX transformations follow circle_rectangle_intersection_area. Volume scales as length cubed and length derivatives as length squared. Interior center motion correctly has zero volume derivative. Near total stock removal, subtraction limits relative accuracy of the remaining volume.

    Example::

    radius = jnp.array(1.8)
objective = lambda r: plate_with_hole_volume(
    jnp.array([1.5, 0.2]), r, jnp.array([3.0, 2.0]), jnp.array(2.0)
)
volume, dvolume_dr = jax.value_and_grad(objective)(radius)

    Opposing planar face contact¶

    brepax.experimental.planar_contact evaluates how intersection volume starts changing when two solids move from a known opposing planar contact. It takes a convex contact polygon and a translation/rotation direction. Unlike the circular-cut example, this is a one-sided directional response, generally nonlinear in direction, with no single gradient representing every motion.

    import jax
import jax.numpy as jnp

from brepax.experimental.planar_contact import (
    planar_contact_volume_direction,
    prepare_planar_contact_patch,
)

jax.config.update("jax_enable_x64", True)
patch = prepare_planar_contact_patch(
    [[-1, -1], [1, -1], [1, 1], [-1, 1]],
    origin=[0, 0, 0], basis=[[1, 0], [0, 1], [0, 0]],
)
tilts = jnp.array([[1.0, 0, 0], [-1.0, 0, 0]])
response = jax.jit(jax.vmap(
    lambda omega: planar_contact_volume_direction(
        patch, jnp.zeros(3), omega, jnp.zeros(3)
    )
))(tilts)
# Both tilts create overlap: response == [1, 1].

    The plane normal is the cross product of the basis columns, outward from the fixed solid. Inputs use one length unit; translation is length per unit of the dimensionless path parameter and rotation is radians per unit parameter. Transform both velocities and the pivot with the geometry under proper rigid motion. Scaling lengths and translation by s scales the response by s**3. Changing the pivot requires the compensating translation documented by the API. Preparation is host-only and requires x64; queries support jit and vmap with a fixed polygon size. Differentiating a response query does not produce the gradient of Boolean volume at contact.

    For actual CAD inputs, prepare_planar_contact_reference in brepax.experimental.planar_contact_cad takes two solids and explicit face IDs. It checks finite convex polyhedra with straight-edged, single-wire planar faces and unique opposing supports. Its required mode distinguishes "zero_residual" from "projected_nominal". Both return a nominal support polygon, with the source gaps, normal residuals, and tolerances retained in prepared.diagnostics; neither certifies exact source contact nor repairs the solids. Even a positive gap below OCCT tolerance changes the derivative. Curved or holed faces, initial overlap, additional contact patches, and general nonconvex CAD are outside this bounded preparation contract.

    Run the grouped estimator comparison and fresh CAD direction-selection example:

    uv run --group benchmark python -m benchmarks.face_contact.run --output /tmp/face-contact.json

    The same finite motion candidates and action step are evaluated with actual CAD volumes. Results include calibration choices, five geometry-group splits, ablations, setup/runtime costs, and unsupported or unresolved cases. A good infinitesimal direction does not certify a finite edit; tiny CAD wedges can fall below OCCT resolution. This experiment does not add a generic optimizer, contact detector, or arbitrary STEP topology-editing API. See ADR-0022 for the decision and the directional derivation.

    brepax.experimental.planar_contact ¶

    One-sided volume response at a known isolated opposing planar contact.

    This is a nonlinear function of a supplied rigid-motion direction, not a custom JVP of Boolean volume or a detector of contact in arbitrary geometry.

    PlanarContactPatch ¶

    Bases: Module

    Convex contact polygon in an oriented orthonormal plane frame.

    Create with :func:prepare_planar_contact_patch outside JAX tracing. vertices are counterclockwise local coordinates without a repeated closing vertex. origin + basis @ vertex gives a world point; the cross product of the basis columns points outward from the fixed solid toward the moving solid. Geometry uses a single length unit.

    The record contains no solids and cannot certify contact or isolation. Keep it fixed when querying motions. Polygon size is static under JIT; vmap over directions does not require padding or changing this size.

    prepare_planar_contact_patch(vertices, *, origin, basis) ¶

    Validate a convex local polygon and its world frame on the host.

    Requires JAX x64. Raises ValueError for nonfinite/malformed inputs, repeated edges, nonpositive area, nonconvexity, or a nonorthonormal frame. Polygon half-plane checks reject negative orientations, including those within roundoff: accepting an uncertain negative sign can admit a thin self-crossing polygon. This conservative check may reject nearly collinear input after a coordinate transform. Frame checks use 64 float64 epsilons as a dimensionless roundoff allowance. This checks represented geometry, not the existence of a physical contact. No vertex is snapped or removed. Near-degenerate or extremely large local coordinates can lose precision and should be recentered by the caller.

    planar_contact_volume_direction(patch, linear_velocity, angular_velocity, pivot) ¶

    Positive one-sided derivative of intersection volume at planar contact.

    The initial interiors must be disjoint, with one isolated opposing contact polygon and positive solid thickness on both sides. For the moving body's path pivot + exp(t*[angular_velocity]_cross) @ (x-pivot) + t*linear_velocity, this returns the integral of max(-normal dot (linear_velocity + angular_velocity cross (x-pivot)), 0). It measures the limit as t decreases to zero from above. A positive gap, existing overlap, or an omitted positive-area contact changes that target.

    Supports jit and vmap over supplied finite directions with a fixed patch. This map is nonlinear in direction; it is not an ordinary JVP of volume. Differentiating this function would differentiate the response model, not the underlying Boolean volume. No derivative of this response map is part of the contract. Invalid motion components return NaN.

    With dimensionless t, linear velocity uses length units, angular velocity radians, and the result volume units. Proper rigid transformations must also transform the frame, pivot, and both velocities. Scaling all lengths and linear velocity by s>0 scales the result by s**3. Changing pivot to p' requires v' = v + angular_velocity cross (p'-pivot) for the same instantaneous motion direction (finite paths can differ at second order). For rigid bodies, union and fixed-minus-moving volume responses have the opposite sign. Finite edits still require an independent volume check.

    Uses exact affine integration over a triangle fan in float64. Very small caps, extreme scales, or cancellation in the represented velocity field can lose relative accuracy; no arbitrary-precision guarantee is made.

    Example::

    jax.config.update("jax_enable_x64", True)
patch = prepare_planar_contact_patch(
    [[-1, -1], [1, -1], [1, 1], [-1, 1]],
    origin=[0, 0, 0], basis=[[1, 0], [0, 1], [0, 0]],
)
# Opposite tilts both create overlap: each response is 1.
value = jax.jit(planar_contact_volume_direction)(
    patch, jnp.zeros(3), jnp.array([1.0, 0, 0]), jnp.zeros(3)
)

    brepax.experimental.planar_contact_cad ¶

    Host preparation of a nominal contact patch from selected planar CAD faces.

    This module prepares a planar contact model, not an exact-contact certificate or a repaired B-Rep. Source gaps and numerical residuals remain visible.

    PreparedPlanarContact dataclass ¶

    Numerical reference patch and host-only source diagnostics.

    PlanarContactDiagnostics dataclass ¶

    Source-CAD evidence, in input length units unless dimensionless.

    plane_distance_range contains signed moving-vertex distances from the fixed plane, whose outward normal points towards the moving solid. signed_plane_gap uses the underlying plane origins. With imperfect opposition there is no single gap, so both quantities are retained. Normal residual is dimensionless. Bounds concern floating-point geometric consistency and never replace a nonzero gap by exact source contact.

    prepare_planar_contact_reference(fixed_shape, moving_shape, *, fixed_face_id, moving_face_id, mode) ¶

    Prepare explicitly selected convex support polygons on the fixed plane.

    Both inputs must be valid finite convex polyhedral solids with planar, convex, single-wire faces and straight edges. Face IDs index the current TopExp_Explorer(shape, TopAbs_FACE) order; rebuilding CAD can change IDs. The selected faces must oppose, be the unique faces on their support planes, and have positive-area overlap after projection. Whole-solid checks exclude competing contacts outside this convex supporting model.

    mode is required. "zero_residual" rejects every computed nonzero plane or normal-opposition residual. "projected_nominal" permits only roundoff-sized residuals and explicitly projects the moving support polygon onto the fixed plane. Both return the projected support-polygon reference, not a repaired solid or a certified derivative of the original CAD. Even a positive source gap below either OCCT tolerance or roundoff has a different contact derivative; inspect the returned diagnostics and establish actual contact independently before applying the reference law to source CAD.

    Lengths retain input units; linear velocities and pivots passed to the evaluator must use these units. Preparation requires JAX x64 and runs on the host. The resulting patch supports the numerical evaluator's JAX transformations. Rigid placement and positive unit scaling preserve the reference geometry up to extraction roundoff. Extreme origin/feature conditioning can fail the consistency checks instead of being snapped.

    Raises ValueError for unsupported geometry, selection, residuals, or mode. No contact search, face healing, or original-solid modification occurs.

    Example, given two known contacting boxes and their selected face IDs::

    prepared = prepare_planar_contact_reference(
    fixed, moving, fixed_face_id=5, moving_face_id=4,
    mode="zero_residual",
)
rate = planar_contact_volume_direction(
    prepared.patch, velocity, angular_velocity, pivot,
)

    Other experimental applications¶

    brepax.experimental.applications.mold_direction ¶

    Mold pull-direction optimization via differentiable undercut analysis.

    Given a shape defined by its SDF, estimates the volume of material that would prevent mold removal in a given pull direction. The undercut criterion is SDF-based: a surface point is undercut when its outward normal opposes the pull direction (dot(normal, direction) < 0).

    Both the undercut volume and the optimization loop are fully differentiable, enabling gradient-based search over the unit sphere S^2.

    MoldDirectionResult dataclass ¶

    Result of mold direction optimization.

    Attributes:

    Name Type Description
    direction Float[Array, 3]

    undercut_volume(shape_sdf, direction, *, lo, hi, resolution=64) ¶

    Estimate undercut volume for a mold pull direction.

    Undercut is defined as the set of interior points whose SDF spatial gradient (outward normal) opposes the pull direction. Both the interior membership and the undercut condition are smoothed with sigmoid indicators scaled by the grid cell width, ensuring the estimate improves with resolution.

    Normals are estimated via central finite differences to avoid NaN gradients at degenerate SDF points (cylinder axis, box center, etc.).

    brepax.experimental.applications.cad_frame.CadFrame dataclass ¶

    Fixed host metadata with x_external = origin + length_scale * x_work.

    length_scale is external length units per working length unit. Choose it once from a reference design size, before constructing CAD, and keep it fixed throughout editing. For a 40 mm reference expressed in metres, use length_scale=0.001 to work at size 40. origin is in external units. Directions/rotations are unchanged by this positive uniform scale; any rigid rotation belongs to the supplied geometry model.

    Array conversions support JIT, vmap and differentiation when this frame is captured as fixed metadata. A degree-k scalar scales by sk and its gradient with respect to external lengths by s(k-1). The frame itself is not a differentiable model. Prefer x64 for CAD accuracy.

    Normalize design dimensions and dimensional meshing/smoothing tolerances BEFORE OCCT construction. This does not infer STEP units, repair existing B-Reps, or guarantee CAD accuracy at arbitrary scales. Output transforms retain OCCT's tolerance semantics; they do not tighten tolerances.
